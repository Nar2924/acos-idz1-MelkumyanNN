### Отчет по индивидуальному заданию №3

**Дисциплина:** Архитектура компьютера и операционные системы
**Тема:** Разработка имитационной программы с использованием взаимодействующих процессов

**Выполнил:** Мелкумян Нарек Норайрович

**Вариант:** 13

#### 1. Условие задачи и исходный сценарий

**Предметный сценарий:** Моделирование работы сада (клумбы) и независимых садовников.

* **Сущности:**

  * **Клумба (Сад):** Содержит заданное количество цветов, каждый из которых имеет свой уровень влажности и индивидуальную скорость высыхания. Сад моделирует течение времени, отслеживая состояние каждого цветка.

  * **Цветы:** Имеют состояния (Нормальный, Увядающий, Засыхающий/Мертвый, Полит).

  * **Садовники:** Независимые работники, которые отслеживают состояние клумбы. При обнаружении увядающего цветка садовник начинает его полив, пополняя уровень влажности со своей индивидуальной скоростью.

#### 2. Архитектура решения и отображение сущностей

Программа спроектирована как многопроцессная система, состоящая из независимых программ, которые запускаются отдельно (в разных терминалах или фоновых процессах).

* **Процесс `garden_app` (Сад):** Выступает в роли главного процесса-инициализатора. Он не имеет графического интерфейса, кроме вывода логов. Его задача — создать объекты межпроцессного взаимодействия (IPC) и моделировать физические процессы в саду (высыхание цветов) с течением времени.

* **Процессы `gardener_app` (Садовники):** Множество независимых процессов, которые подключаются к работающему саду. Количество садовников не ограничено жестко и зависит от числа запущенных экземпляров программы.

**Межпроцессное взаимодействие (IPC):**

1. **Обмен данными:** Осуществляется через разделяемую память стандарта POSIX (системные вызовы `shm_open`, `ftruncate`, `mmap`). В ней размещается структура `SharedGarden`, содержащая общие параметры симуляции и массив состояний всех цветов.

2. **Синхронизация:** Реализована исключительно через именованные POSIX-семафоры (`sem_open`):

   * `SEM_GARDEN_NAME` — семафор-мьютекс для обеспечения эксклюзивного доступа к структуре сада при чтении или изменении данных.

   * `SEM_GARDENER_SYNC` — семафор-сигнализатор, с помощью которого сад будит спящих садовников, когда появляются увядающие цветы.

   * `SEM_START_NAME` — семафор для синхронизации одновременного старта всех садовников после команды от пользователя.

   * `SEM_LOG_NAME` — семафор для потокобезопасной записи логов.

#### 3. Реализация пользовательского интерфейса

Пользовательский интерфейс реализован как CLI.

1. **Настройка сада:** При запуске `garden_app` пользователю предлагается интерактивное меню настройки параметров симуляции (количество цветов, скорости высыхания, объемы полива, время шага и т.д.). Можно ввести свои значения или использовать значения по умолчанию (нажатием Enter).

2. **Запуск садовников:** Садовники запускаются с передачей аргументов командной строки: `./gardener_app <ID> <Скорость>`. Если аргументы не переданы, программа запрашивает их в интерактивном режиме.

3. **Синхронизация старта:** Сад переходит в режим ожидания (через системный вызов `select`) и выводит в консоль уведомления о каждом подключившемся садовнике. Симуляция начинается только после того, как пользователь нажмет `Enter` в окне сада.

4. **Логирование:** Вывод программы информативен и отражает все ключевые события. Для выполнения дополнительного требования логирование ведется в единый файл `simulation.log` с использованием низкоуровневых системных вызовов (`open`, `write`). События пишутся в строгом хронологическом порядке с указанием времени симуляции.

#### 4. Варианты запуска и завершения программы

* **Запуск:**

  1. В первом терминале: `./garden_app` (ввод параметров, ожидание садовников).

  2. Во втором и последующих терминалах: `./gardener_app 1 20.0`, `./gardener_app 2 15.0` и т.д.

  3. Нажатие `Enter` в терминале сада для старта.

* **Завершение:** Независимо от способа запуска, программа завершается корректно с удалением всех IPC-ресурсов (вызовы `shm_unlink`, `sem_unlink`).

  * **Штатное завершение:** Происходит по достижении лимита времени симуляции (параметр `duration`) или если все цветы погибли. Сад подает сигнал завершения (`stop_flag = 1`), будит всех садовников, после чего каждый процесс освобождает память (`munmap`, `close`) и завершается. Сад выводит итоговую статистику.

  * **Принудительное завершение:** Обрабатывается сигнал прерывания с клавиатуры (`SIGINT` / `Ctrl+C`). Обработчик сигнала (`signal_handler`) меняет флаг `g_stop`, после чего процессы аккуратно выходят из цикла, сохраняют статистику и очищают ресурсы ОС.

#### 5. Использование искусственного интеллекта (ИИ)

Основная логика программы уже была реализована до этого, было необходимо разобраться с тем, как правильно связать процессы через Shared memory и POSIX семафоров и разделить на несколько программ. ИИ использовался для написания отчета, после чего был проверен мною и исправлен мною. Также он проверял написание кода и предлагал возможные варианты реализации частей программы. Помимо этого, ИИ помогал мне решать проблемы, возникающие в процессе решения ИДЗ.

* **Оценка полученного кода:** Код ИДЗ проверялся с помощью ИИ, однако потребовал ручных доработок в конфигурации сборки (`Makefile`).

* **Доработка формата вывода:** Вывод в консоль был сделан полностью с помощью ИИ, так как мозговой нагрузки там почти нет.

* **Фиксация правок кода:** У меня на Mac не запускалась команда make, поэтому мне пришлось удалить `-lrt`. После полной проверки функционала моего решения ИДЗ я вернул этот флаг, для работы на линукс. Если он также не будет запускаться на вашем устройстве, многоуважаемый ассистент, с такой ошибкой: 
```
ld: library 'rt' not found 
collect2: error: ld returned 1 exit status
make: *** [garden_app] Error 1
```
То попробуйте убрать этот флаг компиляции в Makefile и все будет замечательно.
